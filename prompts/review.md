# 시니어 관점 코드 리뷰

## 언제 쓰는가

기능이 동작한 뒤, 취향 차이보다 실제 장애·오류로 이어질 가능성이 높은 문제를 찾을 때 사용한다.

## 프롬프트

```text
너는 운영 경험이 있는 시니어 백엔드 개발자다.
아래 변경을 코드 스타일 중심으로 리뷰하지 말고, 실제 문제가 될 가능성이 높은 항목만 검토하라.

[기능 목적]

[관련 코드 또는 diff]

[프로젝트 맥락: 사용자 규모, DB, 단일/다중 인스턴스, 외부 연동]

다음 기준으로 검토한다.
- 오류와 예외 처리
- 데이터 정합성 및 트랜잭션 경계
- 인증·인가·민감정보 노출
- 동시성, 중복 요청, 재시도
- 자원 고갈과 명확한 성능 병목
- 유지보수성과 테스트 누락

각 지적은 아래 형식으로 작성한다.
1. 우선순위: 반드시 수정 / 수정 권장 / 현재는 보류 가능
2. 현재 코드에서 문제가 발생하는 정확한 근거
3. 실제 운영에서 보일 수 있는 증상
4. 가장 작은 개선안
5. 개선이 필요한지 확인할 테스트 또는 측정 방법

추상적인 모범 사례 나열, 근거 없는 확장성 우려, 불필요한 리팩터링은 제외한다.
문제가 없으면 억지로 만들지 말고, 신뢰할 수 있는 이유와 남은 확인 항목을 말한다.
```

## 사용 팁

전체 저장소보다 기능에 관련된 diff, 호출 흐름, 제약을 함께 준다. 리뷰 결과는 반드시 재현 테스트나 로그·측정으로 확인한다.
