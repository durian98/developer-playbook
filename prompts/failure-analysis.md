# 실패 시나리오 분석

## 언제 쓰는가

"정상 동작한다"는 사실만으로 안심하기 어려운 기능, 특히 예약·결제·권한·재고·외부 API 연동처럼 데이터 정합성이 중요한 기능에서 사용한다.

## 프롬프트

```text
코드 품질을 일반적으로 평가하거나 개선안을 먼저 제시하지 마라.
너는 이 기능이 운영에서 실패하도록 조건을 설계하는 테스트 엔지니어이자 공격자다.

[기능 요구사항]

[관련 코드]

[실행 환경과 제약]

먼저 이 기능의 핵심 불변조건을 정의하라.
그다음 아래 상황에서 각 불변조건이 깨질 수 있는지 분석하라.
- 동시 요청
- 같은 요청의 중복 실행과 재시도
- DB 커밋 전후의 예외와 부분 실패
- 서버 재시작·타임아웃
- 외부 시스템의 지연, 실패, 중복 응답
- 잘못되거나 악의적인 입력과 권한 우회
- 데이터량·요청량 증가
- 다중 인스턴스 실행

발견한 시나리오마다 다음을 작성하라.
1. 실패가 일어나는 정확한 실행 순서
2. 현재 구현이 막는 근거 또는 막지 못하는 근거
3. 최소 재현 테스트 또는 관측 방법
4. 현재 프로젝트에서의 영향도와 수정 우선순위
5. 관련된 표준 용어와 후속 검색 키워드(한글·영문)

현재 코드와 환경에서 성립하지 않는 가정은 명확히 제외하고, 추측은 추측이라고 표시하라.
```

## 핵심 원칙

문제 이름을 모르는 상태여도 시작할 수 있다. 먼저 불변조건을 깨뜨리는 실행 순서를 만들고, 그 뒤에 `lost update`, `idempotency`, `TOCTOU` 같은 문제 이름을 붙인다.
