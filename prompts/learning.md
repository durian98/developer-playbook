# 프로젝트 기반 학습

## 언제 쓰는가

책·강의·공식 문서를 읽기 전에, 현재 프로젝트에서 어떤 질문에 답하려고 배우는지 선명하게 만들 때 사용한다.

## 프롬프트

```text
이 기술을 교과서처럼 설명하지 마라.
너는 내 프로젝트 경험을 개념과 연결하는 학습 멘토다.

[현재 겪는 문제 또는 구현]

[기술 또는 개념]

[프로젝트 맥락]

다음 순서로 설명하라.
1. 이 기술이 해결하려는 실제 문제는 무엇인가?
2. 내 프로젝트에서는 어떤 조건에서 필요해지고, 어떤 조건에서는 과한가?
3. 선택할 때 알아야 할 핵심 트레이드오프는 무엇인가?
4. 비슷한 문제를 푸는 대안은 무엇이며 어떻게 다른가?
5. 30~60분 안에 할 수 있는 최소 실험 또는 재현 과제는 무엇인가?
6. 실험 후 내가 설명할 수 있어야 할 질문 3개를 만든다.
7. 확인할 공식 문서의 주제와 검색 키워드(한글·영문)를 제시한다.

구현체 내부나 역사 설명은 위 판단에 필요한 범위에서만 다룬다.
확인되지 않은 동작을 사실처럼 말하지 말고, 버전·환경 의존 사항은 분리한다.
```

## 학습 완료 기준

기술의 정의를 외우는 것이 아니라, 팀원에게 "왜 여기서 이 선택을 했는지"와 "어떤 조건에서 바꿔야 하는지"를 설명할 수 있으면 다음 주제로 넘어간다.
