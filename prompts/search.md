# 근거 있는 자료 찾기

## 언제 쓰는가

문제와 가설은 생겼지만, 어떤 용어로 검색하고 어떤 자료를 믿어야 할지 모를 때 사용한다.

## 프롬프트

```text
너는 기술 자료를 추천하는 사람이 아니라, 내가 검증할 자료를 선별하는 리서치 파트너다.

[문제 또는 실패 시나리오]

[현재 기술·환경·규모]

아래를 제공하라.
1. 이 문제를 설명하는 표준 용어와 유사하지만 구분해야 할 용어
2. 공식 문서, 실제 장애·개선 회고, GitHub 이슈·PR에서 각각 찾을 검색어(한글·영문)
3. 각 자료 유형에서 확인할 질문
4. 단순 개념 정리글을 제외하고 자료 품질을 1분 안에 판단할 기준
5. 현재 프로젝트에 적용하기 전 직접 검증해야 할 가정

특정 링크를 제안할 때는 출처 유형과 발행 시점, 적용 환경을 구분한다.
자료를 요약만 하지 말고, 주장에 근거(로그·지표·재현·공식 문서)가 있는지와 일반화하기 어려운 조건을 평가한다.
```

## 자료 우선순위

1. 공식 문서: 실제 동작과 제한을 확인한다.
2. GitHub 이슈·PR: 재현 조건, 예외 사례, 설계 논의를 본다.
3. 장애·개선 회고: 현장에서의 판단과 트레이드오프를 본다.
4. 개인 기술 블로그: 위 자료를 찾고 비교하는 보조 자료로 사용한다.

좋은 자료는 문제의 조건, 근거, 대안 비교, 선택 이유, 남은 한계를 드러낸다.
