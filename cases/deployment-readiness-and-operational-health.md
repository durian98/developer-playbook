# 배포 준비 상태와 운영 의존성 상태 분리

## 맥락

배포 파이프라인이 애플리케이션의 전체 상태 응답을 성공 조건으로 사용하고, 그 응답에 외부 장치나 선택적 연동의 현재 연결 상태까지 포함된 경우다.

## 불변조건

- 배포 준비 상태는 새 리비전이 핵심 요청을 처리할 수 있는지를 판별한다.
- 필수 설정이 존재하는지와 외부 클라이언트가 현재 연결되어 있는지는 서로 다른 조건이다.
- 운영 진단의 `DOWN`이 자동으로 배포 실패나 프로세스 재시작을 의미하지 않는다.

## 문제와 재현

애플리케이션 프로세스와 데이터베이스가 정상이더라도 외부 장치가 꺼져 있거나 인증에 실패하면 전체 상태가 `DOWN`이 될 수 있다. 배포 파이프라인이 이 집계 결과만 확인하면 정상적으로 교체된 서버를 실패로 오판한다.

반대로 필수 인증 설정 자체가 빠진 상태를 단순한 연결 끊김처럼 취급하면, 안전하게 요청을 검증할 수 없는 서버가 기동될 수 있다. 설정 누락과 런타임 연결 상태를 같은 신호로 표현한 것이 문제다.

## 대안과 결정

전체 운영 상태를 그대로 배포 조건으로 쓰면 구성은 단순하지만, 배포와 무관한 외부 상태가 성공 여부를 흔든다. 배포 전용 상태 그룹을 두고 프로세스가 핵심 요청을 처리하는 데 필수인 내부 의존성만 포함한다.

외부 장치와 선택적 연동은 전체 운영 상태와 경보에서 계속 관측한다. 필수 시크릿이나 인증 설정의 존재 여부는 애플리케이션 시작 단계에서 실패하도록 하고, 실제 클라이언트 연결 여부는 배포 조건에서 제외한다.

모든 핵심 요청이 특정 외부 의존성 없이는 처리될 수 없는 서비스라면 그 의존성을 배포 준비 상태에 포함할 수 있다. 이 경우에도 일시적인 연결 끊김이 배포 롤백이나 프로세스 재시작으로 이어져야 하는지는 별도로 결정한다.

## 검증

- 필수 내부 의존성 정상·외부 장치 미연결 상태에서 배포 준비 응답이 성공하는지 확인한다.
- 외부 장치 미연결 상태가 전체 운영 응답과 경보에는 남는지 확인한다.
- 필수 내부 의존성을 중단했을 때 배포 준비 응답이 실패하는지 확인한다.
- 필수 인증 설정을 제거했을 때 애플리케이션이 안전하게 기동을 거부하는지 확인한다.
- 외부 클라이언트가 올바르게 인증하면 운영 상태가 정상으로 바뀌는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 외부 장치, 에이전트, 선택적 API 연동을 관측하는 서버와 배포 파이프라인.
- 비적용: 외부 의존성 없이는 어떤 핵심 요청도 처리할 수 없고, 그 사실을 배포 준비 상태에 포함하기로 명시적으로 결정한 서비스.
