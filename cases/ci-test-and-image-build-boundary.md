# 테스트 실행 환경과 이미지 빌드 책임 분리

## 맥락

외부 데이터베이스처럼 의존 서비스가 필요한 통합 테스트를 CI에서 실행하면서, 별도의 이미지 빌드 단계도 같은 테스트를 다시 실행하도록 구성된 경우다.

## 불변조건

- 통합 테스트의 성공·실패는 필요한 의존 서비스가 명시적으로 준비된 환경에서만 결정된다.
- 이미지 빌드는 이미 검증된 애플리케이션 산출물을 재현 가능하게 만든다.
- 같은 통합 테스트가 서로 다른 가정의 단계에서 중복 실행되지 않는다.

## 문제와 재현

테스트 전용 데이터베이스를 기동한 CI 단계는 성공했지만, 이미지 빌드 안에서 테스트가 다시 실행되면 그 컨테이너에는 데이터베이스가 없어 연결 실패가 발생했다. 파이프라인의 앞 단계 성공이 뒤 단계의 실행 환경을 보장한다는 가정이 원인이었다.

## 대안과 결정

이미지 빌드 안에 테스트용 의존 서비스를 다시 구성할 수 있다. 하지만 빌드와 검증의 책임이 섞이고, 실패 원인과 실행 비용이 커진다. 외부 의존성이 있는 테스트는 전용 테스트 단계에서 한 번만 실행하고, 이미지 빌드는 테스트를 재실행하지 않는 방향을 선택한다.

외부 의존성이 없는 단위 테스트까지 이미지 빌드에서 금지한다는 뜻은 아니다. 중요한 것은 각 테스트가 어떤 환경을 전제로 하는지와 어느 단계가 그 환경을 책임지는지다.

## 검증

- 테스트 단계가 필요한 의존 서비스를 실제로 기동하는지 확인한다.
- 파이프라인 전체에서 같은 통합 테스트가 중복 실행되는지 확인한다.
- 테스트 이후 이미지 빌드와 애플리케이션 기동 검증을 각각 통과하는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 외부 의존 서비스가 필요한 통합 테스트와 이미지 빌드가 분리된 CI/CD 파이프라인.
- 비적용: 외부 의존성이 없는 단위 테스트까지 이미지 빌드에서 무조건 배제해야 한다는 규칙은 아니다.

## 다음에 확인할 질문

- 이 테스트는 어떤 외부 서비스를 요구하는가?
- 테스트는 어느 단계에서 몇 번 실행되는가?
- 이미지 빌드가 테스트 환경을 우연히 가정하고 있지 않은가?
