# 실시간 알림과 영속 이벤트의 생명주기 분리

## 맥락

하나의 사건을 실시간 팝업과 영속 이력에서 함께 보여 주지만, 실시간 메시지에는 저장된 이벤트 식별자가 없고 팝업 상태와 이력 상태가 같은 배열을 공유하는 경우다.

## 불변조건

- 영속 이력이 필요한 사건은 저장 성공 이후에 실시간으로 발행한다.
- 실시간 메시지는 저장된 이벤트와 동일한 식별자를 전달한다.
- 팝업 닫기·확인 같은 일시적 UI 상태가 원본 이벤트나 감사 이력을 삭제하지 않는다.
- 이력 조회 결과와 실시간 이벤트는 식별자를 기준으로 하나의 사건으로 합쳐진다.

## 문제와 재현

실시간 메시지에 영속 식별자가 없으면 화면은 시각, 유형, 발신자 같은 값으로 저장 이력과 추정 매칭해야 한다. 동시 사건이나 전송 지연이 있으면 다른 사건을 합치거나 같은 사건을 두 번 표시할 수 있다.

팝업과 이력이 같은 상태 배열을 공유하면 사용자가 팝업을 닫는 UI 동작이 이력 행까지 제거할 수 있다. 페이지를 다시 열었을 때 서버 이력과 실시간 행의 관계도 복원하기 어렵다.

## 대안과 결정

실시간 수신 때마다 목록을 다시 조회하고 내용으로 추정 매칭할 수 있지만, 동시성과 지연에 취약하다. 사건을 먼저 저장하고 생성된 식별자를 실시간 payload에 포함한다. 화면은 그 식별자로 상세 조회, 상태 변경, 중복 제거를 수행한다.

팝업의 표시 여부와 닫힘 상태는 해당 UI 컴포넌트에 한정한다. 영속 이벤트 이력은 별도 상태나 서버 조회 결과로 관리하고, 재접속이나 페이지 재진입 때 서버에서 복원한다.

저장할 필요가 없는 순수 휘발성 알림이라면 영속 식별자와 이력 복원은 필요하지 않다. 다만 이 경우에도 팝업 상태와 다른 화면 상태가 우연히 같은 배열을 공유하지 않는지 확인한다.

## 검증

- 저장 실패를 주입했을 때 실시간 이벤트가 발행되지 않는지 확인한다.
- 저장된 식별자와 실시간 payload의 식별자가 같은지 확인한다.
- 같은 식별자의 이력 조회 결과와 실시간 이벤트가 한 번만 표시되는지 확인한다.
- 팝업을 닫거나 확인한 뒤에도 이력 행과 원본 이벤트 상태가 유지되는지 확인한다.
- 페이지 재진입과 재접속 뒤 서버 이력으로 화면이 복원되는지 확인한다.
- 동시에 발생한 유사 사건이 시각이나 내용이 아닌 식별자로 구분되는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 감사, 대응, 상세 조회, 상태 변경이 필요한 실시간 알림과 이벤트 이력 화면.
- 비적용: 세션 안에서 잠시 보여 주고 폐기하는 순수 휘발성 안내.

- payload가 영속 이벤트 식별자를 전달하는가?
- 팝업 닫기·확인이 원본 이벤트 상태나 공용 배열을 변경하는가?
- 재접속 뒤 어떤 저장소가 이력을 복원하는가?
