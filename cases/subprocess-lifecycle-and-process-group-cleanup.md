# 하위 프로세스 적층 문제의 진단·검증 계획

> 상태: 반복 명령 뒤 프로세스가 남았다는 관찰만 있고, 원인과 해결 효과는 검증되지 않았다. 아래 내용은 완료된 프로젝트 트러블슈팅이 아니라 재현과 판별을 위한 조사 기준이다.

## 맥락

서버나 브리지 프로세스가 외부 명령을 반복 실행하고, 그 명령이 다시 여러 자식 프로세스를 만드는 경우다. 시작 요청만 처리하고 이전 실행의 종료를 확인하지 않으면 보이지 않는 프로세스가 계속 남을 수 있다.

## 불변조건

- 같은 역할의 장기 실행 프로세스는 의도한 개수만 존재한다.
- 새 실행은 이전 실행의 종료가 확인된 뒤 시작한다.
- 부모 종료나 모드 전환 시 자신이 만든 프로세스 트리를 정리한다.
- 종료 실패는 숨기지 않고 제한 시간, 강제 종료, 상태 보고로 이어진다.

## 관찰과 먼저 구분할 상태

반복 명령 뒤 종료되지 않은 백그라운드 프로세스가 남았다는 기록은 있지만 PID, PPID, PGID, 상태와 자원 사용량을 함께 남긴 원문이 부족하다. 이미 종료돼 회수만 기다리는 zombie는 일반적으로 CPU를 계속 사용하지 않으므로, 살아 있는 orphan·중복 child와 구분해야 한다.

시작과 중지를 여러 번 반복하면서 프로세스 트리, 활성 인스턴스 수, 자원 사용량을 기록한다. 부모를 비정상 종료한 뒤 자식이 남는지도 확인한다.

## 원인별 해결 후보

중복 start가 원인이면 프로세스 핸들을 소유 상태에 보관하고 start, stop, restart를 직렬화한다. 자식 트리가 남는 것이 확인되면 새 프로세스 그룹이나 세션으로 시작하고, 그룹에 정상 종료 신호를 보낸 뒤 제한 시간 내 끝나지 않을 때 강제 종료하는 방식을 검토한다. 종료된 child를 회수하지 않은 문제라면 wait 처리부터 확인한다.

운영체제 서비스 관리자나 컨테이너가 생명주기를 안정적으로 관리할 수 있다면 직접 spawn하는 코드보다 그 경계를 사용하는 편이 낫다. 단발성이고 즉시 끝나는 명령은 동일한 수준의 관리가 필요하지 않을 수 있다.

## 검증 계획

- start 요청을 동시에 여러 번 보내도 활성 인스턴스 수가 정책을 넘지 않는지 확인한다.
- stop과 restart를 반복한 뒤 남은 자식·좀비 프로세스가 없는지 확인한다.
- 정상 종료를 무시하는 자식을 주입해 제한 시간 뒤 그룹 전체가 정리되는지 확인한다.
- 부모 프로세스의 정상·비정상 종료 뒤 하위 프로세스와 점유 자원이 어떻게 남는지 확인한다.
- 장시간 반복 실행에서 CPU, 메모리, 파일 디스크립터 사용량이 누적되지 않는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 로봇·미디어·빌드 도구처럼 하나의 명령이 자식 프로세스 트리를 만들고 장시간 실행되는 통합.
- 비적용: 짧게 실행되고 운영체제가 종료와 자원 회수를 완전히 보장하는 단발성 명령.
