# 장치 이벤트 판정 교체는 Shadow 검증 뒤 전환한다

## 맥락

센서 입력을 해석해 이벤트를 발행하는 장치의 판정 로직을 교체하는 경우다. 단위 테스트가 통과해도 실제 입력 주기, 센서 좌표계, 전송 지연, 서버의 저장·알림 계약은 테스트 가정과 다를 수 있다.

## 불변조건

- 검증 중인 새 판정기가 운영 이벤트를 중복 발행하지 않는다.
- 라이브 전환 뒤에는 구형과 신규 전송 경로 중 하나만 이벤트를 발행한다.
- 전환 실패 시 실행 파일과 서비스 설정을 함께 되돌릴 수 있다.
- 완료 여부는 장치 로그가 아니라 최종 소비자의 수신까지 확인한다.

## 문제와 재현

새 판정기를 바로 라이브로 전환하면 실제 센서 주기나 좌표 보정 차이가 최초 운영 이벤트에서 드러난다. 구형 경로를 끄지 않은 채 신규 경로를 활성화하면 같은 상황이 두 번 저장되거나 알림이 중복될 수도 있다.

실물 입력을 넣고 후보, 확정, 해제 상태 전이를 관찰한다. 장치가 만든 결정과 서버 저장, 실시간 화면, 외부 알림을 동일 사건 단위로 연결해 비교하면 경계별 불일치를 찾을 수 있다.

## 대안과 결정

새 판정기를 먼저 Shadow 모드로 실행해 실물 입력에서 상태 전이와 근거를 기록하되 운영 이벤트는 발행하지 않는다. 좌표계, 입력 신선도, 전이 조건을 확인한 뒤 라이브 전환 시 구형 발행 경로를 명시적으로 비활성화한다.

전환 전에는 실행 파일뿐 아니라 서비스 인자와 환경 설정도 함께 백업한다. 독립적인 무상태 텔레메트리는 Shadow 단계의 가치가 낮을 수 있지만, 안전·비용 영향이 큰 제어 변경은 Shadow 이후에도 단계적 승인이나 별도 차단 장치가 필요하다.

## 검증

- 동일한 실물 입력에서 Shadow 판정과 기존 운영 결과를 비교한다.
- 후보, 확정, 해제와 센서 장애·복구 전이가 예상 순서로 한 번씩 발생하는지 확인한다.
- 라이브 전환 전후에 이벤트 발행 프로세스가 하나뿐인지 확인한다.
- 장치 결정이 저장, 실시간 화면, 외부 알림까지 동일 사건으로 도달하는지 확인한다.
- 백업한 실행 파일과 서비스 설정으로 실제 롤백 절차를 설명할 수 있는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 센서 융합, 엣지 판정, 장치 경보처럼 실제 입력과 외부 부작용이 결합된 변경.
- 비적용: 운영 부작용이 없고 입력 계약이 완전히 통제되는 독립 계산이나 무상태 텔레메트리.

## 다음에 확인할 질문

- 롤백에 필요한 실행 파일과 서비스 설정은 무엇인가?
- 최종 소비자까지 어떤 식별자로 한 사건을 추적할 수 있는가?
