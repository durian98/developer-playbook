# 엣지 모델 선택은 정확도와 실제 실행 경로 비용을 함께 고정한다

## 맥락

엣지 추론에서는 검증 데이터의 정확도만으로 배포 모델을 고르면 실제 장치에서 지연, 발열, 메모리, 전처리·후처리 비용 때문에 기대한 성능을 내지 못할 수 있다. 반대로 커널 실행 시간만 비교하면 디코딩, NMS, 센서 동기화, 이벤트 확정 규칙을 포함한 실제 응답 시간을 놓친다.

따라서 모델 구조와 운영 규칙은 하나의 실행 경로로 보고 선택해야 한다.

## 지켜야 할 불변 조건

- 데이터 분할과 클래스 매핑을 먼저 고정하고 중복 샘플의 분할 누수를 검사한다.
- 후보 비교는 같은 검증 집합, 입력 크기, 정밀도, 후처리 조건에서 수행한다.
- 최종 홀드아웃은 후보 선택과 임계값 조정에 반복 사용하지 않는다.
- 장치 성능은 모델 커널뿐 아니라 전처리, 추론, 후처리, 시간 누적 규칙까지 포함해 측정한다.
- 최적화 전후 출력 동등성과 클래스별 오차를 확인한다.
- 현장 오탐·미탐과 복구 동작을 재현할 수 있도록 모델·규칙 버전을 기록한다.

## 실패하기 쉬운 접근

### 검증 손실 또는 평균 정확도만 보고 선택

평균 지표가 좋아도 작은 객체, 특정 환경, 중요한 클래스의 재현율이 낮을 수 있다. 운영 임계값과 시간 누적 규칙이 적용되면 순위가 다시 바뀔 수도 있다.

### 복잡한 다단계 구조를 기본적으로 우수하다고 판단

게이트, 재추론, 다중 뷰 같은 단계는 일부 오류를 복구할 수 있지만 고유하게 복구한 사례가 적거나 추가 지연이 크면 단일 모델보다 불리하다. 복잡성 자체가 품질 근거는 아니다.

### 최적화 엔진의 커널 시간만 보고 실시간성을 주장

입출력 복사, 디코딩, NMS, 센서 융합과 이벤트 확정 시간을 제외하면 사용자가 체감하는 지연을 설명하지 못한다.

## 권장 의사결정 절차

1. 후보별 클래스 단위 precision, recall, F1과 오류 사례를 같은 조건에서 비교한다.
2. 임계값과 시간 누적 규칙은 검증 집합에서 조정하고 선택 기록을 남긴다.
3. 대상 장치에서 전체 실행 경로의 p50, p95, 최악 지연과 장시간 실행 시 변화를 측정한다.
4. 최적화 전후 원시 출력과 최종 탐지 결과의 동등성을 확인한다.
5. 복잡한 구조는 단순 구조가 놓친 중요 사례를 얼마나 고유하게 복구하는지, 그 대가로 얼마의 지연과 운영 복잡성이 생기는지 함께 평가한다.
6. 정확도 차이가 작고 복잡한 구조의 고유 이득이 입증되지 않으면 단순한 실행 경로를 우선한다.
7. 마지막에 한 번만 홀드아웃과 현장 재현 세트로 승인 기준을 확인한다.

## 검증 체크리스트

- 데이터셋과 모델 산출물의 버전 또는 해시가 남아 있는가
- 클래스 매핑과 전처리 조건이 학습·변환·배포에서 같은가
- 후보 선택에 사용한 집합과 최종 평가 집합이 분리되어 있는가
- 클래스별 오탐·미탐, 작은 객체와 도메인별 오류를 확인했는가
- 대상 장치의 전체 경로 지연과 장시간 안정성을 측정했는가
- 최적화 전후 출력 동등성을 수치로 확인했는가
- 모델 버전, 규칙 버전, 임계값과 판단 이유가 이벤트에 연결되는가
- 실패 시 이전 모델 또는 보수적 규칙으로 되돌릴 수 있는가

## 적용 범위

영상 탐지뿐 아니라 음성, 센서 이상 탐지, 로봇 제어 보조 등 제한된 장치에서 모델 출력이 운영 판단으로 이어지는 모든 시스템에 적용할 수 있다.
