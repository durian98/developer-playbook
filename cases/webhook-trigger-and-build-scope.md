# 이벤트 수신 범위와 빌드 대상 분리

## 맥락

여러 구성 요소가 하나의 저장소를 공유하고, 각 구성 요소가 별도 CI/CD 파이프라인을 사용하는 환경이다.

## 불변조건

- 한 구성 요소의 변경 이벤트가 관련 없는 파이프라인을 깨우지 않는다.
- 검증 목적의 실행과 병합 뒤 배포 실행이 서로 다른 조건에서 명확히 구분된다.
- 파이프라인이 빌드하는 코드와 수신하는 이벤트 범위가 각각 의도대로 제한된다.

## 문제와 재현

파이프라인의 브랜치 지정은 빌드할 코드를 정할 뿐, 웹훅을 어떤 이벤트에서 수신할지 제한하지 않는 도구가 될 수 있다. 이 차이를 놓치면 다른 구성 요소의 이벤트에도 파이프라인이 실행되거나, 의도한 병합 이벤트가 잘못된 조건으로 거절될 수 있다.

## 대안과 결정

구성 요소별 저장소나 완전히 분리된 파이프라인은 필터 설정을 단순하게 만들지만 관리 대상이 늘어난다. 공유 저장소를 유지한다면 빌드 대상 브랜치와 별개로 대상 브랜치·이벤트 유형을 트리거 조건으로 명시한다. 검증 CI와 병합 후 배포도 분리해 각 실행의 목적을 하나로 유지한다.

## 검증

- 트리거 설정이 이벤트 수신 조건과 빌드 코드 선택을 각각 어떻게 처리하는지 확인한다.
- 구성 요소별 병합 이벤트로 의도한 파이프라인 하나만 실행되는지 확인한다.
- 검증 실행이 배포를 수행하지 않고, 배포 실행이 허용된 병합 뒤에만 동작하는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 여러 구성 요소와 여러 파이프라인이 하나의 저장소 이벤트를 공유하는 환경.
- 비적용: 구성 요소 하나만 있는 저장소에서는 이벤트 필터 분리가 과도한 운영 복잡도가 될 수 있다.

## 다음에 확인할 질문

- 이 설정은 빌드 대상을 고르는가, 이벤트 수신을 제한하는가?
- 어떤 이벤트에서 검증과 배포가 실행돼야 하는가?
- 다른 구성 요소의 이벤트가 들어오면 어떤 파이프라인이 반응하는가?
