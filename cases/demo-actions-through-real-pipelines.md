# 시연 UI는 실제 이벤트 파이프라인을 호출한다

## 맥락

시연 버튼이 경보·상태 변경처럼 실제 운영 흐름을 검증해야 하지만, 화면에는 이미 로컬 mock 상태를 바꾸는 데모 렌더러가 있는 경우다.

## 불변조건

- 시연으로 발생한 이벤트는 운영 이벤트와 같은 저장·실시간 표시·후속 처리 경로를 사용한다.
- 화면의 중복 클릭 방지는 사용자 경험을 위한 보조 장치이고, 중복 이벤트 차단은 서버가 보장한다.
- 실제 데이터로 표시해야 하는 화면에 mock 상태가 섞여 잘못된 관측 결과를 만들지 않는다.

## 문제와 재현

로컬 mock 상태를 직접 토글하면 화면 효과와 로컬 알림은 즉시 보이지만, 서버 이벤트 기록이나 외부 후속 처리와 분리된다. 같은 버튼이 서버 이벤트도 함께 호출하면 로컬 경보와 서버 경보가 중복될 수 있고, 실제 센서·영상 화면에 가짜 상태가 남을 수 있다.

## 대안과 결정

오프라인 프로토타입처럼 시각 효과만 보여 주는 목적이면 mock 토글이 가장 단순하다. 그러나 권한, 이벤트 기록, 실시간 관제, 외부 연동까지 시연해야 한다면 실제 명령 또는 이벤트 진입점을 호출한다.

서버는 호출 주체와 이벤트 유형을 기준으로 짧은 쿨다운 또는 멱등성을 보장한다. 클라이언트도 요청 중·쿨다운 상태를 표시할 수 있지만, 그것을 보안이나 정합성 보장으로 취급하지 않는다.

## 검증

- 시연 요청이 운영 이벤트와 같은 저장·브로드캐스트·후속 처리 경로를 타는지 확인한다.
- mock 상태를 함께 바꾸지 않아도 관제 화면에 필요한 결과가 나타나는지 확인한다.
- 같은 요청을 빠르게 반복하거나 동시에 보내도 서버가 의도한 횟수만 처리하는지 확인한다.

## 적용 범위와 비적용 조건

- 적용: 운영 처리 경로의 정합성까지 보여야 하는 관리자 시연, 테스트 트리거, 장애 훈련 UI.
- 비적용: 서버 연결 없이 순수 화면 전환만 검증하는 프로토타입. 이 경우에는 mock임을 명확히 표시한다.

## 다음에 확인할 질문

- 동일 요청의 반복·동시 호출을 서버가 막는가?
