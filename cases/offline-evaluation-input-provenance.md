# 오프라인 평가는 운영 입력의 원본성과 시간축부터 고정한다

## 맥락

운영 중 저장된 센서 파일로 모델과 판정 규칙을 다시 평가할 때, 화면 표시용으로 가공된 이미지나 갱신 주기가 다른 센서 파일을 그대로 모으면 샘플 수와 입력 분포가 실제 실행 경로와 달라질 수 있다.

## 불변조건

- 평가 입력은 모델 출력이 그려지기 전 원본에서 만들어진다.
- 서로 다른 주기의 센서는 파일 개수가 아니라 관측 시각으로 연결한다.
- 같은 센서 관측이 여러 샘플에 중복 집계되는지 추적할 수 있다.
- 미완결 스트림이나 손상 파일을 정상 샘플처럼 평가하지 않는다.

## 문제와 원인

탐지 결과가 그려진 이미지를 다시 추론 입력으로 사용하면 모델 출력이 다음 평가 입력에 섞인다. 더 느리게 갱신되는 센서 파일을 빠른 카메라 프레임마다 재사용하면 같은 관측이 여러 번 집계되어 성능과 시간 연속성 결과를 왜곡한다.

파일명과 개수만으로 샘플을 묶은 것이 원인이었다. 입력의 생성 단계와 센서별 timestamp가 평가 데이터 계약에 포함되지 않았다.

## 해결과 검증

표시용 이미지 대신 원본 영상 구간을 입력으로 사용하고, 느린 센서는 수정 시각을 기준으로 새 관측만 집계했다. 샘플마다 각 센서의 시각과 시각 차이를 남기고, 기록 중이던 영상은 정상 종료 처리한 뒤 평가했다.

변경 뒤 실제 열원 구간에서 센서 값과 탐지 결과를 다시 재현해 가공 입력과 중복 관측이 제거된 것을 확인했다.

## 적용 범위와 비적용 조건

- 적용: 카메라, 열, 음향, 로그처럼 주기가 다른 운영 데이터를 사후 재생해 평가하는 시스템.
- 비적용: 수집 단계에서 불변 원본과 동기화된 sample ID가 이미 보장되는 데이터셋. 그래도 변환 계보는 확인해야 한다.
