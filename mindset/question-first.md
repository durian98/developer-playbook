# Question First

좋은 개발자는 답을 많이 아는 사람이 아니라, 문제를 깨뜨릴 질문을 먼저 떠올리는 사람이다.

## 이 문서를 사용하는 방법

프로젝트를 진행하면서 모든 프롬프트를 사용할 필요는 없다. 현재 작업 단계에 맞는 질문만 선택해서 AI에게 던진다.

- [Architecture Review](../prompts/architecture.md) → 시스템 경계와 데이터 흐름을 정하는 구현 전
- [Design Review](../prompts/design.md) → 한 기능의 API·데이터·트랜잭션 경계를 좁힐 때
- [Senior Review](../prompts/review.md) → 구현 후
- [Failure Analysis](../prompts/failure-analysis.md) → 테스트 및 검증
- [Retrospective](../prompts/retrospective.md) → 기능 완료 후
- [기술 학습](../prompts/learning.md) → 새로운 개념을 만났을 때

## 먼저 던질 질문

### 요구사항

- 이 기능이 성공했다는 기준은 무엇인가?
- 절대 깨지면 안 되는 사실은 무엇인가?
- 누가 어떤 권한으로 이 행동을 할 수 있는가?

### 구현과 데이터

- 동시에 실행되면 결과가 달라지는가?
- 같은 요청이 다시 오면 두 번 처리되는가?
- 중간에 실패하면 무엇이 남는가?

### 운영과 검증

- 외부 시스템이 느리거나 실패하면 어떻게 되는가?
- 데이터와 요청이 늘면 무엇이 먼저 고갈되는가?
- 이 판단을 틀렸다고 증명할 테스트·로그·지표는 무엇인가?

## 멈추는 기준

모든 가능성을 없애려 하지 않는다. 현재 규모에서 중요한 불변조건과 실패 시나리오를 설명하고, 이를 검증할 방법이 있으면 구현으로 넘어간다.

## 공유 전 경계

프롬프트에 코드·로그를 붙일 때도 비밀값, 내부 URL, 계정·고객 데이터, 아직 수정되지 않은 취약점은 제외한다.
